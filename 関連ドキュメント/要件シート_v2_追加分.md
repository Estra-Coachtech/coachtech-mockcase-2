### C-1. 既存項目「ダミーデータが作成可能か」の詳細補強（修正）

開発プロセスシートの「環境構築」グループにある **「ダミーデータが作成可能か」** 行の「詳細」セルを、現在の Seeder 実装に合わせて以下に置き換える。
これにより採点者は **`php artisan migrate:fresh --seed` 後に user1 でログイン → `/attendance/report`** を開くだけで、画面の数値と「予測値」を突き合わせて採点できる。

**置き換え対象**: 既存行「ダミーデータが作成可能か」の「詳細」セル

**新しい詳細セルの内容**（コピペ用 — ★ 部分は赤字で表記）:

> 下記の情報に対して、ダミーデータの作成が可能であること
>
> ───【基本要件】───
>
> 【ユーザー情報】 管理者ユーザーと一般ユーザーのどちらも作成すること
> - ユーザー1（一般）: `user1@example.com` / `password` / メール認証済み
> - ユーザー2（一般）: `user2@example.com` / `password` / メール認証済み
> - ユーザー3（管理者）: `user3@example.com` / `password` / メール認証済み（`admin_status = true`）
>
> 【勤怠記録情報】 出勤・退勤・休憩時間に関するダミーデータを作成する
> - 全ユーザーに対して、勤怠（`attendance_records`）と休憩（`breaks`）のダミーデータを作成する
> - 件数・日付分布は実装者の裁量
>
> ───【★ 応用要件（マイ勤怠レポート採点用）】───
>
> 応用機能（マイ勤怠レポート）を実装する場合は、user1 に対して以下の **意図的なパターン** を含むデータを作成すること。これにより採点者は `/attendance/report` の表示値と「予測値」を突き合わせて採点できる。
>
> ★【user1 の意図的データ】
> - ★ 過去 5 ヶ月: 各月平日 15 日 = **75 日** の通常勤務（9:00-18:00）
> - ★ 当月 **17 日** のパターン: 通常 10 / 残業（9:00-20:00）3 / 遅刻（9:30-18:00）2 / 早退（9:00-17:00）1 / 長時間労働（8:00-21:00）1
> - ★ user1 の全レコードに **固定休憩 12:00-13:00（1 時間）** を付与
>
> ★【user1 で /attendance/report を開いた時の予測値】
> - ★ 過去 6 ヶ月 総労働時間: **744 時間**
> - ★ 過去 6 ヶ月 総残業時間: **10 時間**（残業判定: 1 日 8 時間超過分）
> - ★ 過去 6 ヶ月 平均労働時間 / 日: **8 時間 5 分**
> - ★ 当月 遅刻回数: **2 回**（始業 09:00 超過）
> - ★ 当月 早退回数: **1 回**（終業 18:00 より前の退勤）
> - ★ 当月 長時間労働回数: **1 日**（1 日 10 時間超）

### E-3. AP01: 勤怠一覧API

| 項目 | 内容 |
|---|---|
| エンドポイント | /api/v1/attendance-records |
| メソッド | GET |
| 認証 | 不要 |
| 認可（ポリシー） | - |
| 説明 | 勤怠一覧を取得する。検索・絞り込み・ページネーション対応 |

リクエストパラメータ

| パラメータ名 | 型 | 必須 | 説明 | 例 |
|---|---|---|---|---|
| user_id | integer | 任意 | ユーザーIDで絞り込み | 1 |
| date | date | 任意 | 日付で絞り込み（YYYY-MM-DD） | 2026-05-01 |
| month | string | 任意 | YYYY-MM 形式の年月で絞り込み | 2026-05 |
| page | integer | 任意 | ページ番号（デフォルト: 1） | 2 |
| per_page | integer | 任意 | 1ページあたりの件数（デフォルト: 20、最大: 100） | 20 |

レスポンス

| ステータス | 説明 | レスポンスボディ例 |
|---|---|---|
| 200 OK | 取得成功 | `{ "data": [{ "id": 1, "user_id": 1, "user_name": "山田太郎", "date": "2026-05-01", "clock_in": "09:00:00", "clock_out": "18:00:00", "total_time": "08:00", "total_break_time": "01:00", "comment": "..." }], "links": { ... }, "meta": { "current_page": 1, "from": 1, "last_page": 5, "per_page": 20, "to": 20, "total": 100 } }` |

実装方法/補足

| 内容 |
|---|
| `Api\V1\AttendanceRecordController@index` |
| `Api\V1\IndexAttendanceRecordRequest` で user_id/date/month/page/per_page をバリデーション（すべて nullable） |
| `AttendanceRecord::with('user', 'breaks')` で関連を eager load |
| `when()` で user_id/date/month をフィルタリング |
| `latest('date')->paginate($perPage)` でページネーション（デフォルト20件、最大100件 — `IndexAttendanceRecordRequest` 側で max:100 を強制） |
| `AttendanceRecordResource::collection($attendanceRecord_records)` を return（Laravel が自動的に data + links + meta を付与） |

### E-4. AP02: 勤怠詳細API

| 項目 | 内容 |
|---|---|
| エンドポイント | /api/v1/attendance-records/{attendanceRecord} |
| メソッド | GET |
| 認証 | 不要 |
| 認可（ポリシー） | - |
| 説明 | 指定IDの勤怠詳細（ユーザー・休憩・修正申請含む）を取得する |

リクエストパラメータ

| パラメータ名 | 型 | 必須 | 説明 | 例 |
|---|---|---|---|---|

### E-8. ★ AP06: Sanctum APIトークン認証（応用）

公開API の書き込み系エンドポイント（POST/PUT/DELETE）に Laravel Sanctum を導入し、認証＋認可を行う。

| 項目 | 内容 |
|---|---|
| 認証方式 | Bearer トークン（Authorization ヘッダ） |
| 対象エンドポイント | POST /api/v1/attendance-records, PUT /api/v1/attendance-records/{attendanceRecord}, DELETE /api/v1/attendance-records/{attendanceRecord} |
| 認可ポリシー | AttendanceRecordPolicy。update / delete は本人のみ |

導入手順

| 手順 | コマンド/設定 |
|---|---|
| 1. パッケージ導入 | `sail composer require laravel/sanctum` |
| 2. 設定 publish | `sail artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"` |
| 3. マイグレーション | `sail artisan migrate`（personal_access_tokens テーブル作成） |
| 4. User モデル | `HasApiTokens` トレイトを追加 |
| 5. ルート保護 | `routes/api.php` の POST/PUT/DELETE ルートを `Route::middleware('auth:sanctum')->group(...)` で囲む |
| 6. 認可 | `Api\V1\AttendanceRecordController` の update/destroy で `$this->authorize('update'\|'delete', $attendanceRecord)` を呼ぶ |
| 7. トークン発行 | テストでは `Sanctum::actingAs($user, ['*'])` を使用 |

### E-9. API Resource の構造

一覧API（index）と詳細API（show）で **同一の AttendanceRecordResource** を共用する。`whenLoaded('breaks')` / `whenLoaded('applications')` により、関連データは eager load されたとき（詳細API）のみレスポンスに含まれ、一覧API では自動的に省略される。

| Resource | フィールド | データ元 |
|---|---|---|
| AttendanceRecordResource | id | $this->id |
|  | user_id | $this->user_id |
|  | user | UserResource（whenLoaded('user')） |
|  | date | $this->date |
|  | clock_in | $this->clock_in |
|  | clock_out | $this->clock_out |
|  | total_time | $this->total_time |
|  | total_break_time | $this->total_break_time |
|  | comment | $this->comment |
|  | breaks | AttendanceBreakResource::collection（whenLoaded('breaks')） |
|  | applications | ApplicationResource::collection（whenLoaded('applications')） |

### E-10. エラーレスポンスの統一

すべてのエラーは `app/Exceptions/Handler.php` で集中管理する。

| 例外 | HTTPステータス | レスポンスボディ |
|---|---|---|
| `ModelNotFoundException`（api/* パスのみ） | 404 | `{ "error": "勤怠情報が見つかりませんでした。" }` |
| `ValidationException` | 422 | `{ "message": "...", "errors": { ... } }` |
| `AuthenticationException`（応用） | 401 | `{ "message": "Unauthenticated." }` |
| `AuthorizationException`（応用） | 403 | `{ "error": "この操作を実行する権限がありません。" }` |
